## 0. 一句话定位

**用户进入 Studio 后 10 秒内知道第一步做什么；从一句话创意到第一张分镜图，不超过 3 次操作。**

v2 把"画布优先"的骨架立起来了，但节点和入口是历史叠加的产物：
同一件事有 3~4 个入口、参数编辑分裂在两处、8 种节点 7 种颜色、隐形规则看不见。
v3 不加任何新功能，**只做减法和统一**。

## 1. 现状审计

### 1.1 入口冗余审计（核心问题）

| 操作 | 现有入口（数量） | v3 决策 |
|---|---|---|
| **运行节点** | ① 节点底部全宽大按钮 ② 选中浮动工具条 ▶ ③ Inspector 底部「生成」 ④ ⌘Enter（共 4 个） | **保留 ②④**。砍掉①（节点卡片瘦身的最大头）和③（随 Inspector 一起移除） |
| **删除节点** | ① Delete 键 ② 浮动工具条 🗑 ③ Inspector 底部「删除节点」（共 3 个） | **保留 ①②**，砍掉 ③ |
| **新增节点** | ① 双击空白 ② 拖线出菜单 ③ 左栏面板「+」 ④ Composer（共 4 个） | **保留 ①②④**（各有场景：凭空建/顺流建/一句话起链）。③ 随面板简化降级为资产库内部动作 |
| **编辑参数** | 节点内联（prompt/brief）+ Inspector（tone/比例/输出）**双入口分裂** | **全部上节点**，移除右侧 Inspector（详见 §4.2） |
| **重命名标题** | 仅 Inspector 顶部 input | **双击节点标题改名**（TapNow 同款），Inspector 移除后这是唯一入口 |

> 原则：每个操作一个主入口 + 一个快捷键，不再有第三个。

### 1.2 逐节点审计（对照 `src/studio/types.ts`）

| 节点 | 参数 | 问题 | v3 决策 |
|---|---|---|---|
| **script** | brief / tone / length | tone、length 只能去 Inspector 改，brief 却在节点上——同一节点编辑分裂 | tone/length 做成节点内紧凑下拉，与 brief 同区 |
| **storyboard** | screenplay / splitter / mode | `splitter`（手动分隔符）暴露在节点和 Inspector 两处，95% 用户用不到 | 默认隐藏 splitter；mode=manual 时才展开。screenplay 留空用上游的规则要**显式可见** |
| **image** | prompt / aspectRatio / `referenceImage?` | ① 节点上写死 "gemini-3.1-flash-image" 元信息无操作价值 ② `referenceImage` 参数存在但**无任何 UI 可设置**（死参数）③ "prompt 留空自动用上游"是隐形规则 | ① 删死文案 ② 删死参数（上游参考图已由连线自动收集）③ 节点顶部加「上游输入」指示条 |
| **scene** | description / aspectRatio | 与 character/prop 共用 GridImageNode，结构 OK | 统一进节点规范 v3 |
| **character / prop** | description / `referenceImage?` | `referenceImage` 同样是**无 UI 的死参数**（store 里会读，但用户无法设置） | 删除死参数，参考图统一靠连线（上传素材节点 → 连入） |
| **shot** | shotDescription / aspectRatio | **4 个分色输入桩**（文本/场景/角色/道具）：要求用户记住颜色对应关系，连错桩无提示；TapNow 是单输入自动收集 | 砍成**单输入桩**：上游文本自动当描述、上游图片自动当参考（store 已是这个逻辑，桩位只是装饰性复杂度） |
| **asset** | note | `note` 参数定义了但**无 UI**（死参数） | 删除参数，类型收敛为无参数节点 |
| **全部** | — | 状态徽章中英混杂：`gen` / `ready` / `error` / 紫点(idle)；ImageNode 还有独立一套 | 统一：`待运行` / `生成中` / `完成` / `失败`，一处实现（shared StatusBadge），删除 ImageNode 的本地副本 |

### 1.3 布局与焦点审计

当前同屏浮动元素：左上角按钮组（↶↷?+提示文字）、左栏 8 个工具、顶栏 4 个按钮、
底部 Composer、右侧浮动 Inspector、节点工具条——**6 类浮层**，无主次。

| 问题 | 细节 | v3 决策 |
|---|---|---|
| 左栏 8 工具 | 「剧本/分镜/场景/镜头/角色/道具/素材/音画」本质都是"按类型筛资产"，但视觉权重等同于主导航；「音画」是占位假功能 | **砍为 1 个「资产」按钮**，打开统一资产抽屉（内部按类型分 tab）；音画占位移除 |
| 右侧 Inspector | 与节点内联编辑完全重复（§1.1） | **整体移除**。参数上节点、重命名双击、输出编辑进节点 |
| 顶栏假项目名 | "《无声之城》· Ch.2 auto-saved" 是写死的假数据 | 改为可编辑的真实工程名（存 localStorage，导出 JSON 带上） |
| 状态徽章/提示文字 | 左上角"双击空白新建节点 · 拖图片进画布作参考"常驻文字 | 收进 ? 帮助浮层，首次进入自动展示一次 |
| 节点配色 | 7 种 accent 色（橙橙青橙黄绿紫紫青），无法形成记忆 | **收敛为 3 色语义**：文本类=橙（script/storyboard）、图像类=紫（image/scene/character/prop/shot）、素材=青（asset） |
| 首次进入 | 预置示例图 + 默认选中 script-1，没有"从这里开始" | **空画布 + 中央引导卡**（§4.3） |

| TapNow | 我们 v2 | v3 目标 |

| 简洁节点卡（图为主，按需露操作） | ❌ 信息密度过高 | ✅ 节点规范 v3 |
| 空画布有起点引导 | ❌ 预置假图 | ✅ 中央引导卡 |

## 3. 设计原则

1. **单一入口**：每个操作一个主入口 + 一个快捷键，删掉所有第三入口。
2. **节点自治**：一个节点的所有编辑在节点上完成，不需要看第二个面板。
3. **渐进披露**：高级参数（splitter 等）默认折叠；操作按钮选中/悬浮才出现。
4. **空状态即引导**：每个空白处都回答"现在该做什么"。
5. **诚实 UI**：界面上每个可点击元素必须真实可用（延续 v2 原则）。

## 4. 新设计方案

### 4.1 页面 wireframe

```
┌────────────────────────────────────────────────────────────┐
│ ← 返回 ｜ Logo ｜ [工程名✎]      分享 · 运行管线 · ⬇ · ⋯  │ ← 顶栏（不变，项目名改真）
├────────────────────────────────────────────────────────────┤
│ ┌──┐                                                       │
│ │资│   [↶ ↷ ?]                                             │
│ │产│                                                       │
│ └──┘        满 屏 画 布                                     │
│  ↑          （选中节点 → 节点上方工具条：▶ ⧉ ⬇ 🗑）        │
│  唯一左栏入口                                               │
│                                                            │
│            ┌────────────────────────────┐                  │
│            │ ✦ 一句话描述你的创意…       │ ← Composer        │
│            │            [创建管线][创建并运行]│   （唯一焦点）  │
│            └────────────────────────────┘                  │
└────────────────────────────────────────────────────────────┘
```

- **左栏**：只剩「资产」一个按钮 → 打开统一资产抽屉（tab：全部/剧本/分镜/图像/角色/素材），
  内容为画布真实产出（沿用现有面板数据逻辑，合并为一个组件）
- **右侧**：无任何常驻/浮动面板
- **Composer**：视觉权重最高（描边渐变高亮），是页面唯一"从这里开始"的焦点

### 4.2 节点卡片规范 v3（统一解剖）

```
┌─────────────────────────────┐
│ ◉ 图标 标题(双击改名)   ●状态 │ ← 头部：单行，状态=色点+中文
│ ┄┄┄ ⤓ 上游输入 ×2 ┄┄┄        │ ← 有连线才出现的指示条（解决隐形规则）
│ ┌─────────────────────────┐ │
│ │      预览（图/文本）      │ │ ← 主体，占卡片 70%
│ └─────────────────────────┘ │
│ prompt 输入（2 行自适应）     │ ← 参数区：主参数 textarea
│ [16:9 ▾] [电影感 ▾]          │ ←        次参数：紧凑下拉一行排
└─────────────────────────────┘
   选中时浮出 → [▶ 运行] [⧉] [⬇] [🗑]   ← 唯一可视运行入口
```

变更要点（对照 §1.2 逐条落实）：
- **砍掉底部全宽运行按钮**（所有节点）——运行靠工具条/⌘Enter
- **状态徽章统一**：`待运行`(灰) `生成中`(橙脉冲) `完成`(绿) `失败`(红)，仅 shared 一处实现
- **上游输入指示条**：有入边时显示"⤓ 上游输入 ×N（文本/图×M）"，点击高亮上游节点；
  prompt 为空时占位文案明示"将使用上游输出"
- **双击标题重命名**（inline input，Esc 取消 Enter 确认）
- **shot 单输入桩**；**删除死参数**（image/character/prop 的 referenceImage、asset 的 note）
- **storyboard 的 splitter** 折叠进"高级 ▾"，mode=manual 才展开
- 配色 3 色语义（文本橙/图像紫/素材青）

### 4.3 首次体验（空画布）

新工程/清空后，画布中央显示引导卡组：

```
        从一个模板开始，或在下方输入一句话 ↓
   ┌─────────┐  ┌─────────┐  ┌─────────┐
   │ 🎬 短剧  │  │ 📦 产品广告│ │ 🎵 MV    │
   │ 剧本→分镜 │  │ 场景+道具 │  │ 场景→分镜图│
   │ →分镜图   │  │ →合成    │  │          │
   └─────────┘  └─────────┘  └─────────┘
```

- 点模板卡 → 铺出对应预连节点链（复用 `createPipelineFromBrief` 模式扩展）
- 画布上有任意节点时引导卡消失
- 默认工程不再预置示例节点（现 `defaultGraph.ts` 的演示图改为「模板」之一）

## 6. 验收标准

1. 任一操作（运行/删除/新增/改参/改名）入口数 ≤ 2（主入口+快捷键）
2. 编辑任何节点参数**不需要打开任何面板**
3. `types.ts` 中不存在无 UI 入口的参数字段
4. 状态文案全站统一中文，单处实现
5. 空画布首屏有且仅有一个视觉焦点链：引导卡 → Composer
6. 新用户路径：输入一句话 → 创建并运行 → 得到分镜图，全程 2 次点击

## 7. 不做清单（Non-goals，本期不碰）

- 视频节点 / 真时间线（P2-7）
- R2 图片托管（P2-6）

- 节点类型合并重构（image/scene/shot 数据模型层面的整合，仅做视觉收敛）
