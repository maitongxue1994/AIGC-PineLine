# PineLine 运维手册（上线部署 + 监控 + SOP）

## 一、首次上线部署 runbook（严格按序）

商业化改造引入了访问门（fail-closed）、积分账本 DO、R2 交付、Paddle 支付。**部署顺序错了会锁死线上**，务必按下面走。

### 步骤 0：先配 secret（否则推代码后线上生成全部 503）

CF Dashboard → Workers & Pages → aigcpineline0419 → Settings → Variables and Secrets：

| 名称 | 类型 | 值 | 必需 |
|---|---|---|---|
| `PINELINE_ACCESS_CODES` | Secret | 逗号分隔，如 `admin-一串随机,试用-abc123` | **是（不配则 503）** |
| `PINELINE_ALLOWED_ORIGINS` | Secret | `https://你的域名,https://aigcpineline0419.mys2388212.workers.dev` | 建议 |
| `PINELINE_MAX_RES` | Var | 不设 = 非管理员封顶 1080p；设 `4k` 放开 | 否 |
| `PADDLE_WEBHOOK_SECRET` | Secret | Paddle 后台 webhook 密钥 | Paddle 上线时 |
| `PADDLE_PRICE_MAP` | Var | `pri_xxx:6000,pri_yyy:20000`（price_id→积分） | Paddle 上线时 |

`admin-` 前缀的码 = 你自己用（免限流、免扣费、可上传交付、可充值）。

### 步骤 1：建 D1/R2 资源（DO 自动创建，无需手动）

- R2 桶：CF Dashboard → R2 → 创建桶，命名 **`pineline-delivery`**（与 wrangler binding 一致）。不建则交付上传返回 501，不影响其他功能。
- Durable Objects（CanvasBridge/CreditLedger）：Workers Build 跑 wrangler deploy 时自动按 migrations 创建，无需手动。

### 步骤 2：同步 deploy/cloudflare 分支的 wrangler.jsonc

main 分支 wrangler.jsonc 已加 CREDIT_LEDGER DO（migration v2）+ R2 binding。**deploy 分支的 wrangler.jsonc 独立维护，必须手工同步等价配置**（durable_objects 两个 binding + migrations v1/v2 + r2_buckets）。用 git worktree：

```bash
git worktree add /tmp/pl-deploy origin/deploy/cloudflare
# 编辑 /tmp/pl-deploy/wrangler.jsonc 加 CREDIT_LEDGER binding + migration v2 + r2_buckets（注意 assets.directory=./public）
cd /tmp/pl-deploy && git add wrangler.jsonc && git commit -m "deploy: 同步 CreditLedger DO + R2 配置" && git push origin HEAD:deploy/cloudflare
```

### 步骤 3：推 main 触发部署

`git push origin main` → ~5 分钟生效。**注意**：main push 会先同步 worker 代码到 deploy 分支（sync-deploy），确保 CreditLedger 类已到 deploy 分支后，步骤 2 的配置才能构建成功——所以顺序是「先推 main（带代码）→ 再改 deploy 分支 wrangler」。若已按步骤 2 先改了 wrangler 但代码没到，会构建失败，重跑即可。

### 步骤 4：清理废弃 secret

部署生效后：GitHub 仓库 Settings → Secrets 删 `VITE_PINELINE_API_KEY`；CF 删 `PINELINE_API_KEY`（已无人消费）。

### 步骤 5：验证

```bash
BASE=https://你的域名
curl $BASE/api/health                    # {ok:true}
curl -X POST $BASE/api/generate/script -H 'content-type: application/json' -d '{}'   # 无码 403 ACCESS_REQUIRED
# 浏览器带 admin- 码生成一次 → CreditsPill 显示 ∞；带试用码生成 → 扣积分、余额下降
```

## 二、日常 SOP

- **发/停访问码**：改 `PINELINE_ACCESS_CODES` secret，即时生效。给客户发 `试用-xxx` 码。
- **给客户码充值**（收款后）：用 admin 码调 `POST /api/admin/credit`：
  ```bash
  curl -X POST $BASE/api/admin/credit -H "X-Pineline-Access: admin-你的码" \
    -H 'content-type: application/json' -d '{"code":"试用-abc","amount":6000,"note":"闲鱼订单#123"}'
  ```
- **查客户余额流水**：客户自己在 Studio 点积分胶囊看；你可用其码调 `/api/account`。
- **改定价**：`src/siteConfig.ts` 的 PRICING（展示价）+ `src/worker/pricing.ts` 与 `src/studio/nodeCatalog.ts`（扣费费率，两处必须同步，`npm run test:billing` 会校验一致）。
- **看后台日志**：URL 加 `?admin=1` → 历史面板「日志」tab（本地生成日志 + 云端实例日志）。

## 三、监控告警（30 分钟配完）

- **BetterStack**（免费档）：监控 `$BASE/api/health`，3 分钟间隔，带状态页（给 to B 客户看加分）。UptimeRobot 作冗余。
- **Cloudflare**：Notifications → 开 Workers 用量通知（邮件）。
- **火山方舟**：控制台 → 财务 → 开「资源包余量预警」（阈值 30%）+「账单消费预警」。
- **MiniMax**：账户 → 余额 → 设余额预警金额。
- 全部指向常用邮箱 + 绑手机短信。

## 四、大陆可达性

- workers.dev 在大陆被墙。**买自有域名绑 CF Custom Domain**（免备案走海外解析，大陆大概率可达但速度一般），改 `src/siteConfig.ts` SITE_ORIGIN + `index.html` 域名 + `PINELINE_ALLOWED_ORIGINS`。
- 国内 to B 交付不依赖客户访问网站：R2 交付链接或微信/网盘发成片。
- 字体已自托管（去 Google Fonts），大陆首屏不再卡字体。

## 五、成本护栏回顾

- 访问门（fail-closed）+ 限流（video 12/h 等）+ 预扣积分（余额不足 402）+ 视频分辨率封顶 1080p + 非管理员强制供应商水印。四层叠加，模型成本永远由已收款覆盖。
